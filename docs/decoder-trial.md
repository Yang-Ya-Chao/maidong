# FFmpeg 音视频解码试用

本次是本地试用改动，未提交 Git。目标设备上的画面、声音、性能和同步效果需要手动验证。

## 实现

- 主引擎：Media3 ExoPlayer 1.7.1。
- 音视频软件解码：NextLib `1.7.1-0.9.0`，该版本构建脚本使用 FFmpeg 6.0。
- 原生库打包架构：`armeabi-v7a`、`arm64-v8a`。
- 保持 `minSdk 21`、`targetSdk 25`；为匹配扩展库的 Kotlin 元数据，构建插件调整为 Kotlin 2.1.21 和 AGP 8.10.1。
- 系统与 FFmpeg 音频都经过相同的 PCM 声道、音量和升降调处理，关闭 HDMI 压缩音频直通。
- 主视频、内置双音轨副播放器和外置原伴唱音频使用同一播放引擎。

## 自动解码（当前行为）

应用统一自动选择解码器，设置页不再提供手动解码入口，升级前保存的系统/兼容选择也不再生效。主视频、外置音频和内置副音轨启动及下一首均从 AUTO 状态开始。

系统解码优先，按格式能力选择可用路径。明确的音频或视频解码错误只切换对应轨道，允许系统与 FFmpeg 双向尝试；同一轨道切换一次后仍失败便报错，不反复切换。播放器已就绪且请求播放、但 5 秒仍没有视频首帧时，也进入这条恢复路径；暂停、缓冲和音频副引擎不触发该检查。

可用解码路径耗尽后停止当前播放，交由歌曲队列跳过该曲；外层歌曲重试不再重新打开同一个解码失败文件。网络和文件读取错误保留原来的有限重试。

重建保留既有的进度、播放意图和 KTV 音频控制，副音轨继续通过原有恢复回调同步。网络、HTTP、权限、文件缺失、普通解析和音频输出设备错误不盲目切换解码器。初始 MKV 索引越界仍使用一次顺序读取恢复，异常文件可能无法跳转。

内部模式枚举仅保留作诊断能力，用户无需选择；实际解码器与恢复过程通过日志记录。

## 支持范围

本次扩展版本声明的视频解码器为 H.264、HEVC、VP8、VP9；音频包括 AAC、MP3、AC-3、E-AC-3、DTS、TrueHD、FLAC、ALAC、Opus、Vorbis 等。MKV 解封装仍由 Media3 完成。

这不是所有编码、所有配置均能播放的保证，也没有增加转码或录制编码器。AV1、旧式视频编码、特殊封装或损坏文件仍需另行评估。软件解码的流畅度受盒子 CPU、分辨率和码率影响。

## 手动验证

1. 安装 `app/build/outputs/apk/debug/app-debug.apk`。该 Debug 包应用 ID 为 `com.local.ktv.qa`，与正式版并存，使用独立数据和授权；需要在试用版配置媒体源或选择 U 盘目录。
2. 准备不同来源 MKV：常规 H.264 + AAC、HEVC、AC-3 或 DTS 音轨、双音轨原伴唱，以及左右声道原伴唱素材。
3. 对同一歌曲分别选择系统和兼容解码，确认弹窗中的实际解码器名称，检查画面、声音、首帧、跳转及音画同步。
4. 在暂停和播放时分别切换解码，确认进度与暂停状态保留；检查小窗与全屏、切页、切歌、重唱。
5. 检查原伴唱、左右声道、音量、升降调，以及内置和外置副音轨同步；特别留意解码重建后的同步。
6. 重新打开应用，确认模式保存。自动模式下测试系统不支持的样本；断网或失效链接应走原有媒体源错误处理，不反复切换解码。
7. 在目标 32/64 位盒子上分别检查原生库加载和连续播放；高分辨率素材记录卡顿、温度和音画偏移。

## 兼容性完善（2026-10-15）

兼容模式改为 FFmpeg 优先并保留系统解码器，避免 MPEG-4 等格式因强制移除系统解码器而没有视频输出。明确选择“系统解码”仍保持系统模式。

对 MKV/WebM 开播时、未出首帧且位置为 0 的 2008 读取越界错误，允许一次关闭跳转读取 Cues 索引的恢复。该恢复只作用于当前媒体，并在手动切换解码器时保留；下一首重置。异常文件可能只支持顺序播放，解码信息会显示“索引异常，暂不支持跳转”。播放中途 I/O、EOF、网络和其他错误不走这条恢复路径。

Surface 切换与网络 MKV 样本的设备回归记录见 [decoder-validation/README.md](decoder-validation/README.md)。原伴唱、音调、逐音轨切换和长时间音画同步仍需要 Android TV 真机验收。
