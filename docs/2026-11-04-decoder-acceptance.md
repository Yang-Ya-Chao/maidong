# 解码器补充实测

## 范围与结果

2026-11-04 在 Nox / Android 7.1.2 中对生产 KtvPlaybackEngine 执行 27 项检查，最终 DONE failures=0。测试入口仅存在于 Debug 构建。

- H.264 + 双 AAC 音轨 MKV：ExoPlayer、FFmpeg、自动模式分别验证实际视频帧输出、非零 PCM、暂停、时长范围内的定位、第二音轨、左右声道处理、音调参数、回到起点重播、Surface 更换。
- 自动模式的正常 AAC 样本使用 ExoPlayer，实际解码器为 OMX.google.h264.decoder / OMX.ffmpeg.aac.decoder；FFmpeg 模式使用原生 FFmpeg / h264 / aac。
- 可控故障注入：自动模式从 ExoPlayer 切到原生 FFmpeg，保留暂停状态、进度、音轨、声道、音量、音调；恢复播放后确实重新输出视频帧。FFmpeg 再失败不循环重试，固定 ExoPlayer 不跨内核切换，停止操作取消待执行回退。
- 自然格式兼容：双 MP1 音轨 MKV 在 ExoPlayer 中只有画面、无可选音轨且不主动报错；修复后固定 ExoPlayer 返回错误，自动模式探测到真实音轨后自然回退 FFmpeg，两个音轨均可选择。后续正常 AAC 歌曲重新从 ExoPlayer 开始。

## 本次发现与修复

仅依赖播放器错误回调无法发现被解析器静默忽略的音轨。现在只在 ExoPlayer 已就绪但未识别到任何音轨时，使用不启动播放、不绑定 Surface 的原生音频会话补充探测。发现文件实际含有音轨才判定兼容失败；探测结果随切歌、停止或释放取消，正常文件不增加这次探测。

首轮测试中有定位失败是假阳性：约 6 秒样本被固定定位到 12/32 秒，已改为按样本实际时长选择测试位置。最终回退恢复检查记录：2232ms → 3213ms，25 个新视频帧，错误数 0。
