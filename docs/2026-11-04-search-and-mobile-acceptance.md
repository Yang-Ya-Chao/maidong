# 检索布局与扫码连接修复验收

## 修复内容

- 输入键盘四行按剩余高度均分，取消每行固定 56dp；按键文字随可用空间缩放。
- 搜索左右两栏按实际测量宽度分配，统一栏间距；播放器按 16:9 和可用高度约束布局。
- 快搜头像区从固定 132dp 改为随列表实际高度分配；歌曲行按剩余空间精确分配，避免最低行高使最后一行越界。
- 歌曲信息、状态图标随行高布局，文字自适应。
- 网络检测暂时取不到地址时保持已有监听服务；地址变化时更新访问地址而不重启监听器，保留端口和进行中的请求。
- 手机网页由连续三次状态心跳失败判定断联，搜索等请求单次失败不再立即改变连接提示；轮询串行执行，恢复前台/网络可用后主动重连。

## 已记录的验证

- Nox 7.0.6.2 / Android 7.1.2，独立 Debug 包 `com.local.ktv.qa`。
- 960×540 / 160dpi：A–Z、123 切换、0–9、返回 ABC 均可见；输入 Z 后返回搜索结果；点击下一页后切换至第 2 页。
- 960×540 快搜列表：列表范围 y=150–496，头像范围 y=156–276，三行歌曲范围分别为 y=276–347、347–418、418–490，末行完整处于列表内部。
- 1280×720 / 240dpi 最终包复查：列表范围 y=225–654，三行歌曲范围 y=381–469、469–557、557–645；六首结果及歌手名完整显示，分页按钮底部 y=708，小于屏幕高度 720。
- 普通歌名页同时验证：10 首歌曲及歌手名完整显示，列表范围 y=285–654，末行范围 y=574–645；语种筛选和分页按钮未与列表重叠。
- 真实应用服务 `/mobile`、JS、CSS、Logo、状态、队列、热歌、搜索接口均返回 HTTP 200。
- 四并发 120 次状态/队列请求，120/120 成功，持续约 15 秒，覆盖网络监测周期。
- LocalRemoteServer 地址更新回归：端口保持一致，进行中的慢请求仍返回 200。
- 生产手机网页在 Nox WebView Chrome 92 中运行：搜索请求故障不误报断联，短暂心跳失败不误报，连续失败提示断联，恢复请求后自动连接成功。
- 最终包在 1280×720 下再次通过同一组连接测试；重连后连续 30 秒状态保持 connected=true、心跳失败数为 0。
- Node 网页连接回归验证：单次搜索失败、短暂失败、持续断联、恢复连接、单轮询任务、后台暂停均通过。
- Android JVM 单元测试 102 项全部通过。Debug 构建成功。
- Lint 仍有三项既有错误：API 21 的 foreground 调用、既有布局 0dp 属性、targetSdk 商店要求。

## 范围

手机网页验收使用模拟器 WebView 访问真实应用的本机服务；没有连接实体手机，未将该结果表述为真实手机扫码、路由器隔离或 Wi-Fi 切换的硬件验收。Nox 使用 NAT，模拟器内网二维码地址不保证能被实体手机直接访问。
